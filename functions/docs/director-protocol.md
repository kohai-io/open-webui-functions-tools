# Runway pipe: Studio Director mode

Version 3.1.0 adds an optional structured API to `runway_inline.py`. Install the updated source into the existing Open WebUI function, preserving its model ID and valves, then enable `ENABLE_STUDIO_API`. Normal chat generation and its confirmation settings continue unchanged.

Version 3.1.1 adds optional `providerTaskId` and `failureCode` response fields without changing protocol version 1. It persists a bounded provider failure code with the job and returns the actual Runway task UUID, distinct from Studio's `jobId`. Arbitrary upstream failure messages and URLs are not stored or returned. Studio maps the code to an understandable explanation and exposes the diagnostic code/task ID in Provider details. Both `CANCELED` and `CANCELLED` provider spellings are handled.

The pipe adds a nullable `failure_code` column to an existing mapping database under a SQLite write transaction. Existing mappings and completed jobs are preserved. Previously failed tasks have no stored failure code; this update does not re-query them or submit replacements. New failures retain their code across repeated status requests and duplicate submit calls. Older Studio images ignore the new fields, and newer Studio images show a generic failure message when using an older pipe.

Studio authenticates to Open WebUI as the current user and selects this pipe through `/api/chat/completions`. The last user message contains JSON:

```json
{"studio_director":{"version":1,"operation":"capabilities"}}
```

The pipe returns JSON as completion content. Capabilities report whether the Studio API is enabled and which inputs it accepts. No media is generated by a capability check.

Submission uses `operation: "submit"`, a UUID `jobId`, `confirmed: true`, `prompt`, `duration`, `ratio` and optional `firstFrameFileId`. The current protocol uses Seedance 2.5 at 720p with audio, 4–30 seconds, and accepts one first-frame image. It rejects last frames and extra references. Private images are resolved with Open WebUI file access checks and sent through the existing Runway upload helper.

Poll `operation: "status"` with the same `jobId`. Results contain `state`, `jobId` and, on success, `fileIds` for user-owned Open WebUI video files. Studio never parses the chat player or uses temporary CDN URLs as durable outputs.

The pipe records ownership, submission hashes, provider task IDs and delivered file IDs in the separate `DATA_DIR/studio-runway-jobs.sqlite3` database. Keep it on persistent storage and include it in backups. Reusing the same submission ID with identical inputs does not create another paid task. Changed inputs with the same ID are rejected. A response lost before a task ID is recorded stays `submission-unknown`; verify it in Runway rather than blindly resubmitting.

Status and failed downloads can retry. Output import uses a lease to prevent concurrent imports; a crash after a file is saved but before recording it may leave an extra file, never an extra generation. This initial protocol does not expose cancellation of submitted tasks.

Tests: from `functions_tools`, run `python -m unittest discover -s tests -p test_director_protocol.py`. Tests use fake APIs and temporary storage, with no Runway requests.
